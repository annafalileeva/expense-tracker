# Check layout (desktop + mobile)

Проверяет вёрстку фронтенда (`apps/web`, Next.js App Router, порт 3000) на
двух вьюпортах через Playwright MCP и выдаёт отчёт по найденным проблемам.
Запускается **после** правок во фронтенде — как быстрый визуальный
регресс-чек перед коммитом/PR.

## Аргументы

`$ARGUMENTS` — **необязательный** один аргумент, страница для проверки:

- Полный URL (`http://localhost:3000/expenses`) — берётся как есть.
- Путь (`/expenses`, `expenses`, `/expenses/new`) — достраивается до
  `http://localhost:3000<путь>`.
- **Пусто** — проверяются все страницы приложения (см. § «Список страниц»).

Если аргумент не разобрать (не URL и не похоже на путь маршрута) —
переспросить у пользователя, а не угадывать.

## Вьюпорты

| Профиль | Размер       | Назначение                            |
| ------- | ------------ | ------------------------------------- |
| Десктоп | `1440 × 900` | основной рабочий размер               |
| Мобайл  | `390 × 844`  | iPhone 14/15, самый ходовой мобильный |

## Практика

### 1. Убедиться, что dev-сервер поднят

```bash
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/login
```

Если код не `2xx`/`3xx` — сервер не запущен. Не запускать его молча в
фоне: сказать пользователю выполнить `! npm run dev` (или запустить
самому в фоне, если пользователь просит) и дождаться, пока порт 3000
ответит, прежде чем продолжать.

### 2. Определить набор страниц

- **Аргумент передан** → одна страница из аргумента.
- **Аргумента нет** → собрать все маршруты из
  `apps/web/src/app/**/page.tsx` (`Glob`), отбросив группы `(auth)` /
  `(dashboard)` из пути. Динамические сегменты (`[id]`) — см. § «Список
  страниц»: для них нужен реальный id либо страница пропускается с
  пометкой.

Дополнительно посмотреть `git diff --name-only main...HEAD -- apps/web`
(и `git status`) — какие страницы/виджеты затронуты текущими правками. В
отчёте пометить их как приоритетные; если аргумента нет, начинать
проверку с них.

### 3. Авторизоваться (для страниц под `(dashboard)`)

`proxy.ts` редиректит без сессии на `/login`. Публичные страницы
(`/login`, `/register`, `/privacy`, `/terms`) проверяются без входа;
всё остальное требует сессию.

Завести одноразового пользователя через форму регистрации (это положит
httpOnly-cookie в контекст браузера Playwright):

1. `browser_resize` 1440×900 → `browser_navigate` на
   `http://localhost:3000/register`.
2. `browser_snapshot`, заполнить форму (`browser_fill_form` /
   `browser_type`) уникальными данными — email вида
   `layoutcheck+<timestamp>@example.com`, имя `Layout Check`, пароль
   `Password123!` (свериться с zod-схемой
   `features/auth/register/model/schema.ts`, если поля/правила другие).
3. Отправить, дождаться редиректа на `/` (`browser_wait_for`).

Если регистрация упала (API не поднят на :3001, юзер уже есть) —
сообщить об этом и проверить хотя бы публичные страницы, не выдумывать
результат для закрытых.

### 4. Для каждой страницы — прогон по двум вьюпортам

Для вьюпорта (сначала десктоп, потом мобайл):

1. `browser_resize` на размер профиля.
2. `browser_navigate` на URL страницы (для мобайла — повторный
   navigate/reload уже после resize, чтобы сработали адаптивные брейкпоинты).
3. `browser_wait_for` — дождаться, пока пропадут скелетоны/спиннеры и
   отрисуется контент.
4. `browser_snapshot` — снять дерево доступности.
5. `browser_take_screenshot` с `fullPage: true` и осмысленным именем
   файла: `<slug>-<desktop|mobile>.png` (например `expenses-mobile.png`).
   Файлы уходят в `.playwright-mcp/`.
6. `browser_evaluate` — быстрые числовые проверки, которые не видны на
   скриншоте:

    ```js
    () => {
    	const de = document.documentElement;
    	const overflowX = de.scrollWidth - de.clientWidth;
    	const wide = [...document.querySelectorAll('body *')]
    		.filter((el) => el.getBoundingClientRect().right > de.clientWidth + 1)
    		.slice(0, 10)
    		.map(
    			(el) =>
    				el.tagName.toLowerCase() + (el.className ? '.' + String(el.className).split(' ').join('.') : ''),
    		);
    	return { viewport: window.innerWidth, scrollWidth: de.scrollWidth, overflowX, wide };
    };
    ```

7. `browser_console_messages` (level `error` + `warning`) — собрать
   ошибки JS, 404 на ассеты, предупреждения React/Next о гидрации.

### 5. На что смотреть (чеклист вёрстки)

- **Горизонтальный скролл** — `overflowX > 0` или непустой `wide[]`:
  какой-то элемент вылезает за вьюпорт (чаще на мобайле — широкие
  таблицы, `min-w`, фиксированные `w-`, длинные строки без переноса).
- **Перекрытие / налезание** элементов, текст поверх текста, контент под
  фиксированным хедером/сайдбаром.
- **Сайдбар на мобайле** — `widgets/sidebar` рендерится всегда
  (`w-64 shrink-0`), мобильного drawer/бургера нет: проверить, не
  сжимается ли основной контент в нечитаемую полоску на 390px. Это
  известное слабое место — фиксировать явно.
- **Обрезанный / не влезающий текст**, кнопки без подписи, поехавший
  `truncate`.
- **Пустые состояния и скелетоны** — не съехали, не наложились.
- **Формы** (`/login`, `/register`, `/expenses/new`, `/expenses/[id]/edit`,
  `/categories`, `/settings`) — поля на всю ширину контейнера, лейблы и
  ошибки на месте, submit-кнопка видна без скролла на мобайле.
- **Картинки/иконки** — не битые (нет 404 в консоли), не разъехавшийся
  aspect-ratio.
- **Ошибки в консоли** — любой `error`, а также warning про hydration
  mismatch считаем проблемой вёрстки.

### Список страниц

При пустом аргументе проверяются (пути — уже без групп `(auth)`/`(dashboard)`):

| Путь                  | Доступ    | Примечание                                                                                                                                       |
| --------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/login`              | публичный | форма                                                                                                                                            |
| `/register`           | публичный | форма                                                                                                                                            |
| `/privacy`            | публичный | статика                                                                                                                                          |
| `/terms`              | публичный | статика                                                                                                                                          |
| `/`                   | сессия    | дашборд                                                                                                                                          |
| `/expenses`           | сессия    | список (таблица — кандидат на overflow)                                                                                                          |
| `/expenses/new`       | сессия    | форма                                                                                                                                            |
| `/expenses/[id]/edit` | сессия    | нужен реальный id расхода — взять из ответа `/expenses` или создать через `/expenses/new`; если расходов нет, пропустить с пометкой «нет данных» |
| `/categories`         | сессия    | список + форма                                                                                                                                   |
| `/settings`           | сессия    | форма                                                                                                                                            |

Список маршрутов всегда сверять с фактическим `apps/web/src/app/**/page.tsx`
(`Glob`) — таблица выше могла устареть.

### 6. Отчёт

Свободной формой, но по структуре:

```
# Проверка вёрстки — <дата>

Проверено страниц: N  ·  вьюпорты: 1440×900, 390×844
Затронуто текущим диффом: <список или «—»>

## <путь страницы>
- Десктоп: OK  ·  скрин: .playwright-mcp/<slug>-desktop.png
- Мобайл: ПРОБЛЕМА  ·  скрин: .playwright-mcp/<slug>-mobile.png
  - горизонтальный скролл: scrollWidth 520 при вьюпорте 390 —
    вылезает `table.min-w-[480px]` в списке расходов
  - сайдбар занимает 256px, на контент остаётся ~120px
- Консоль: чисто  /  <текст ошибки>

## Итог
<2–4 предложения: где всё в порядке, что чинить в первую очередь.
Если аргумент был задан — только про эту страницу.>
```

Правила отчёта:

- Для каждой страницы — вердикт по **каждому** вьюпорту (`OK` /
  `ПРОБЛЕМА`) и путь к скриншоту.
- Проблему описывать конкретно: какой элемент, какое число (ширина,
  перекрытие в px), на каком вьюпорте — чтобы можно было чинить, не
  перезапуская проверку.
- Не чинить вёрстку в рамках этого скилла — только диагностика. Найденные
  проблемы вынести списком; правки — отдельной задачей.
- В конце `browser_close`.
