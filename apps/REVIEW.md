# Правила код-ревью

Чек-лист для ревью PR в этом репозитории. Общие правила по коммитам, веткам
и структуре PR — в корневом `CLAUDE.md`; здесь — что именно проверять в диффе.

## Общее

- [ ] PR — одно логическое изменение, без посторонних правок «заодно».
- [ ] Ветка названа `<type>/<kebab-case-description>`, коммиты — по
      [Conventional Commits](https://www.conventionalcommits.org/) (`feat`,
      `fix`, `refactor`, `chore`, `docs`, `test`, `style`, `perf`, `build`,
      `ci`), сообщения в повелительном наклонении.
- [ ] `npm run typecheck` и `npm run lint` проходят по затронутым воркспейсам.
- [ ] Версия TypeScript (`5.9.3`) не разъехалась между `package.json`
      воркспейсов.
- [ ] Нет неиспользуемого кода, закомментированных блоков, `// removed`
      заглушек вместо удаления.
- [ ] Комментарии объясняют «почему», а не «что» — если комментарий просто
      пересказывает код, его не должно быть.
- [ ] Изменение не шире задачи: без преждевременных абстракций и
      «на будущее» обработки случаев, которые не могут произойти.

## apps/api (Nest.js, CQRS)

- [ ] Структура модуля соблюдена: `commands/`, `queries/`, `dto/`,
      `<feature>.controller.ts`, `<feature>.module.ts`; хендлеры, а не
      контроллер, содержат бизнес-логику.
- [ ] Контроллер инжектит только `CommandBus`/`QueryBus`, не `PrismaService`
      напрямую.
- [ ] **Граница между модулями не нарушена**: из другого фиче-модуля
      импортируются только классы команд/запросов и их result-типы из
      `commands/index.ts` / `queries/index.ts` — не хендлеры, не
      `<Feature>CommandHandlers`, не `PrismaService` другого модуля.
- [ ] Каждый модуль явно импортирует `CqrsModule` (он не глобальный в
      `@nestjs/cqrs` v11).
- [ ] Новые эндпоинты либо защищены глобальным `JwtAuthGuard` по умолчанию,
      либо осознанно помечены `@Public()` — если помечены, это оправдано
      (health-check, регистрация, логин).
- [ ] `userId` берётся из `@CurrentUser()`, а не из тела запроса; каждый
      read/update/delete в `expenses`/`categories` фильтрует по
      `{ id, userId }` (или `where: { userId, ... }`), а не по одному `id` —
      иначе открывается доступ к чужим записям.
- [ ] `passwordHash` и другой чувствительный `UserWithCredentials`-шейп не
      выходит за пределы `modules/users`/`modules/auth`; наружу отдаётся
      `UserView`/DTO без него.
- [ ] Ошибки Prisma (P2002, P2025, P2003) не перехватываются вручную в
      хендлере — это делает `PrismaExceptionFilter`.
- [ ] DTO покрывают все поля запроса; лишних полей в теле не появляется в
      обход `ValidationPipe` (`whitelist`/`forbidNonWhitelisted: true`).
- [ ] `Expense.amount` остаётся `Decimal`, не приводится к `number`/`Float`
      на бэкенде.
- [ ] Пути контроллеров не дублируют глобальный префикс `api`.

## apps/web (Next.js, Feature-Sliced Design)

- [ ] Слои FSD не нарушены: импорты идут только вниз
      (`views → widgets → features → entities → shared`), никогда вбок между
      слайсами одного слоя и никогда вверх.
- [ ] Импорт из чужого слайса — только через его `index.ts`, а не напрямую в
      `ui/`/`api/`/`model/` (кроме задокументированного исключения для
      `proxy.ts` → `entities/session/lib/decode-jwt`).
- [ ] Фронтенд не ходит в БД напрямую: из `@expence-tracker/database` берутся
      только типы, данные — только через `apps/web/src/shared/api/*` /
      `entities/*/api/*`. Никакого `PrismaClient` в коде `apps/web`.
- [ ] Денежные суммы форматируются через `formatMoney()`
      (`shared/lib/format.ts`), не через `Number()`/шаблонные строки —
      `ExpenseDto.amount` приходит строкой.
- [ ] Новые API-вызовы лежат в `entities/<feature>/api/<feature>.api.ts`, не
      ad-hoc `fetch()` по компонентам.
- [ ] Чтение — через Server Components и `serverApiFetch`; мутации — через
      Server Actions (`'use server'`) с последующим `revalidatePath`.
      `"use client"` — только на интерактивных листьях (формы, фильтры,
      навигация), а не на целых страницах/композициях.
- [ ] `redirect()` в Server Action вызывается вне `try/catch`.
- [ ] Новые UI-примитивы добавлены через `npx shadcn@latest add <name>` в
      `shared/ui/*`, а не написаны руками.
- [ ] Zod-схема в `features/*/model/schema.ts` синхронизирована с
      валидацией соответствующего DTO на бэкенде (если менялось одно —
      проверить второе).

## Безопасность

- [ ] Ни один новый маршрут не читает/не пишет данные другого пользователя
      без проверки `userId`.
- [ ] JWT/секреты не логируются и не попадают в тело ответа.
- [ ] CORS/origin по-прежнему берётся из конфига (`WEB_ORIGIN`), не
      захардкожен.
- [ ] Новые поля пользовательского ввода валидируются на бэкенде (DTO +
      `class-validator`), а не только на фронтенде.

## PR-описание

- [ ] Тело PR написано по диффу (`git diff main`), а не по памяти о
      намерении.
- [ ] Для изменений в `apps/api` есть секция `## API changes` с новыми/
      изменёнными эндпоинтами.
- [ ] Есть `## Test plan` с реально выполненными проверками
      (`typecheck`/`test`/`lint`, ручные запросы, ручная проверка UI в
      браузере для фронтенд-изменений), без общих шаблонных фраз.

## Пропускать при ревью
- Файлы миграций Prisma (`prisma/migrations/**`)
- `package-lock.json` и другие lock-файлы
- `*.log` файлы
